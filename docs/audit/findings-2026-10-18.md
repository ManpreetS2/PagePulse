# PagePulse audit findings (2026-10-18)

Risk-ranked after reading the repo, installing, typechecking, running all 68 tests, and building successfully.

## Critical / High

| ID | Area | Finding | Disposition |
| --- | --- | --- | --- |
| H1 | Security | DNS TOCTOU / rebinding: `assertSafeUrl` resolves DNS, then `fetch()` resolves again. A malicious hostname can flip to a private IP between check and connect. | **Fixed** — fetcher pins connections to validated addresses via custom DNS lookup. |
| H2 | Reliability | Monitors left in `status='checking'` after a crash/restart are excluded from the scheduler forever (`NOT IN ('paused','checking')`). | **Fixed** — recover on startup + age-out during scheduler ticks. |
| H3 | Security | IPv4-mapped IPv6 forms like `::ffff:7f00:1` were only blocked by “unparseable ⇒ unsafe”, not explicit mapping. | **Fixed** — explicit decode of dotted and hex-mapped forms in `isPrivateIp`. |

## Medium

| ID | Area | Finding | Disposition |
| --- | --- | --- | --- |
| M1 | Correctness | `alertsCreated` counted every qualifying change, including duplicates that did not create a notification. | **Fixed** — count unique notifications only. |
| M2 | Security | No baseline security headers (`X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, CSP). | **Fixed** — defensive headers on all responses. |
| M3 | Reliability | Per-domain rate limiting can delay many monitors on the same host by one tick each; they stay due (OK) but lack visibility. | **Deferred** — safe delay; improving queue visibility is polish, not a correctness bug. |
| M4 | UX | When a check finds noise but no alert, the “why quiet” evidence is buried in the full change history. | **Fixed** — quiet report on check outcome + monitor detail. |

## Low / Portfolio

| ID | Area | Finding | Disposition |
| --- | --- | --- | --- |
| L1 | DX | No ESLint config / lint script; CI already runs typecheck + test + build. | **Deferred** — adding a linter is a new toolchain; CI already gates quality. |
| L2 | Reliability | Snapshot table grows without retention (failure snapshots included). | **Deferred** — optional retention policy; not urgent for local single-user use. |
| L3 | Features | No webhook/RSS channel; email is optional SMTP only. | **Deferred** — README already lists this; keep stack free of new services. |
| L4 | Features | JS-rendered SPAs often yield few sections. | **Deferred** — would need headless browser (heavy new dependency). |
| L5 | Security | App is intentionally unauthenticated (single-user local). | **Accepted** — documented product scope. |
| L6 | XSS | Stored page text is rendered via React text nodes (escaped); no `dangerouslySetInnerHTML`. | **Verified OK** — headers add defense in depth. |
| L7 | Tests | Strong unit + integration + eval coverage; no dedicated scheduler recovery or DNS-pin tests before this PR. | **Fixed** — new tests added. |
