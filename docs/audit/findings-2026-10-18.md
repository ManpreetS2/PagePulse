### Install notes (no `legacy-peer-deps`)

`.npmrc` with `legacy-peer-deps=true` was **removed**. Vitest 4 peers are satisfied by declaring `vite@^6.4.4` on both client and server.

**Exact error without a lockfile on npm 10.9.9** (ideal-tree rebuild):

```text
npm error Cannot read properties of null (reading 'edgesOut')
TypeError: Cannot read properties of null (reading 'edgesOut')
    at #loadPeerSet (.../npm/node_modules/@npmcli/arborist/lib/arborist/build-ideal-tree.js:1289:38)
```

This is an npm 10 arborist bug while resolving Vitest 4’s optional peer set — not a hidden peer conflict. Workarounds that keep audit honest:

1. **`npm ci` / `npm install` with the committed lockfile** — works on npm 10 (CI path).
2. **Regenerate the lockfile with npm ≥ 11** (`npx npm@11 install`) — no `.npmrc` needed; then commit the lockfile.

CI uses `npm ci` on Node 22, so the gate does not depend on `legacy-peer-deps`.

### Rate-limit UX (40/min expensive)

Expensive POSTs: `/preview`, `/monitors/:id/check`, `/evaluation/run`, `/demo/start`, `/demo/continue`, `/samples/load`.

| UI flow | Expensive calls |
| --- | --- |
| Full guided demo | **5** (1 start + 4 continues) |
| Eval suite run | **1** |
| Lab mutation toggle / reset | **0** (not classified expensive) |
| Single “Check now” | **1** |
| Double-click “Check now” | Client busy-guard ignores the second click; server would return **409** if raced |

Normal UI never approaches 40/min. Client surfaces **429** and **409** via `formatApiError` with clear copy; Check now treats 409 as a status message (not a broken error state).
